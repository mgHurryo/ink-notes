# Ink Notes Review Remediation Plan

## Summary

基于 `plan/reviews/REVIEW-2026-09-09-INK-INPUT.md` 和当前仓库实现，分两阶段完成：

1. 先修复数据安全、手写输入一致性、保存生命周期和同步性能问题。
2. 再完成页面生命周期、紧凑响应式 UI，以及一个可验证的 Obsidian 原生价值闭环。

首个原生价值闭环确定为 Markdown `ink` 代码块嵌入页面预览。嵌入格式采用：

````markdown
```ink
Ink Notes/My Notebook.ink
page: page-id
```
````

第二行可省略；省略时显示第一个页面。

## Implementation Changes

### 1. 数据安全与模型兼容

- `NotebookStore.save()` 对磁盘内容解析失败时直接终止保存并抛出可识别错误，禁止用空白 notebook 覆盖原文件。
- 保存失败时保留内存 dirty 状态，显示可定位的 Notice；不进行无限自动重试。
- notebook schema 升级为 `2`，`normalizeNotebook()` 继续兼容 schema 1：
  - 增加 `pageOrder: string[]`；
  - 增加带删除时间的页面墓碑，例如 `deletedPages: Record<string, number>`；
  - 旧文件按现有 `createdAt` 顺序生成 `pageOrder`。
- `mergeNotebooks()` 使用确定性规则：
  - 页面和笔迹按 ID 合并；
  - 页面删除墓碑优先于旧页面内容，禁止跨设备复活；
  - 页面顺序使用 `pageOrderUpdatedAt` 较新的版本，随后补入并发新增页面；
  - 页面至少保留一个可编辑页面。
- 页面删除、复制、移动都通过命令记录，支持撤销和重做。
- “移动”定义为同一 notebook 内调整页面顺序；跨 notebook 移动不纳入本次范围。

### 2. Pointer 生命周期与保存一致性

- 将 pointer 状态收敛为带 generation 的 interaction context，至少锁定：
  - `pointerId`；
  - `pageId`；
  - `tool`；
  - 起始页面和必要的 stroke/lasso 引用。
- `pointerdown` 后工具或页面切换时，先安全结束当前 interaction，再应用新状态。
- `pointerup` 可以采集最终事件坐标；`pointercancel` 和真实 capture loss 只结束当前 interaction，不采集其坐标。
- 结束逻辑只使用 pointerdown 时保存的页面和工具，不读取结束时变化的 `this.state.tool` 或当前 `pageIndex`。
- 关闭视图、切换文件前：
  - 先结束或提交活动 interaction；
  - 清除保存定时器；
  - 按 dirty revision 无条件执行一次 flush；
  - 等待统一的保存 Promise，不暴露底层 rejection。
- 保存队列改为受控串行循环：
  - 保存期间的新修改只增加 dirty revision；
  - 保存快照完成后，若 revision 仍有变化则继续一轮；
  - 失败后 dirty revision 不前移；
  - 所有等待者得到已处理错误的结果，避免未处理 Promise rejection。

### 3. 渲染、橡皮擦和套索性能

- `StrokeIndex.sync()` 将笔迹几何/样式变化与数组位置变化解耦：
  - 笔迹 ID、点集、样式或几何变化才触发相关 tile invalidation；
  - 删除前部笔迹不再使后续所有笔迹的 tile revision 全部递增；
  - 查询结果仍保持正确的合成顺序。
- `TileRenderer` 暴露当前页的局部 stroke 查询能力，橡皮擦只扫描命中空间单元中的候选笔迹。
- 橡皮擦在同一 PointerEvent/frame 内合并删除：
  - `eraseAt()` 不立即重复同步；
  - 采样结束后只执行一次 index sync 和 render request；
  - pointerdown 单击删除成功后立即请求渲染，保证旧 tile 不残留。
- 套索 drag 开始时缓存：
  - 初始 bounds；
  - 选中的 stroke 引用；
  - 初始 points；
  - 起始 page ID。
- 套索移动按 animation frame 合并，结束时强制 flush 最后一个 pending point。
- `boundsForPointSets()` 改为迭代计算，禁止对大型数组使用展开参数的 `Math.min(...values)` / `Math.max(...values)`。
- `applyPointerSamples()` 每个 PointerEvent 只读取一次页面 rect，再转换所有 coalesced samples。

### 4. Vault 事件同步

- 删除 `main.ts` 中每 2.5 秒刷新所有视图的轮询。
- 接入已有的 `NotebookStore.observe()`：
  - 只处理发生变化的 `.ink` 文件；
  - 对同一文件做短 debounce；
  - 同一文件存在进行中刷新时只保留一次 pending refresh；
  - 所有异步刷新统一捕获并报告错误。
- 保存路径增加自身写入抑制标记，并以 notebook revision/equality 检查作为兜底，避免自身保存事件触发无意义重载。
- 外部修改发生在 pointer interaction 期间时继续排队，interaction 结束后再 merge。
- `reloadFromDisk()` 对内容未变化的结果不重建页面、tile state 或 UI。

### 5. 页面生命周期与 notebook 入口

- 页面 rail 增加：
  - 删除当前页面，最后一页时禁用删除；
  - 复制当前页面，复制出的页面和笔迹使用新的 ID；
  - 上移/下移页面；
  - 页面选择和当前页定位。
- 页面操作更新 `pageOrder`、时间戳和同步墓碑，并进入 undo/redo。
- `openNotebook()` 不再无条件打开文件列表第一项，改用 Obsidian `SuggestModal<TFile>` 提供 notebook 搜索选择；没有文件时继续创建默认 notebook。
- 页面菜单只保留一个入口，统一命名为页面操作；移除“Document options”和“Options”的重复入口。
- 增加“复制当前页面嵌入语法”入口，生成当前 `.ink` 路径和 page ID，降低 Markdown 嵌入使用门槛。

### 6. Markdown 嵌入预览

- 插件注册 `ink` Markdown code block processor。
- 解析规则：
  - 第一行是 Vault 相对 `.ink` 文件路径；
  - 可选第二行格式为 `page: <page-id>`；
  - 路径必须位于 `Ink Notes/` 且扩展名为 `.ink`；
  - 无效路径、无效页面或 JSON 损坏时显示明确的内联错误状态，不抛出未处理异常。
- 预览使用现有笔迹绘制能力和页面纸张样式，按页面比例渲染静态预览，不复用完整编辑器交互状态。
- Markdown 预览组件监听目标文件的 Vault modify 事件，文件变化时只刷新对应嵌入；组件卸载时移除监听。
- 预览提供打开原 notebook/定位页面的命令入口，但不在 Markdown 预览中启用编辑或写盘。

### 7. UI 与响应式重构

- 将当前文档栏、主工具栏、笔刷栏、底部状态栏收敛为一条不超过 `56px` 的紧凑工具栏。
- 一级控制只保留：
  - 页面；
  - 笔；
  - 荧光笔；
  - 橡皮；
  - 套索；
  - 撤销/重做；
  - 溢出菜单。
- 颜色、宽度、透明度放入当前工具 popover；不同时常驻显示宽度预设、滑块、自定义颜色和重复工具入口。
- 移除白色普通笔迹预设，恢复可见的黄色荧光笔预设；白色修正液不作为本次功能。
- 使用 Obsidian 语义 CSS 变量替代固定深色应用皮肤，纸张和笔迹颜色保留必要的固定值。
- 页面 rail 默认折叠，移动端一级功能不能因宽度被静默隐藏；次级功能进入 overflow。
- 触摸目标保持至少 `44px`，弹层具备键盘焦点进入、退出和 Escape 关闭行为。
- 画布首屏验收门槛：
  - 桌面视图可用高度至少 `88%`；
  - 移动端和 split pane 至少 `80%`；
  - 360px 宽度下一级工具无横向滚动；
  - 480px、720px 和桌面布局不出现控件重叠或文字溢出。
- 保持 `isDesktopOnly: false`，只有通过上述移动端验收后才继续发布移动支持承诺。

## Public Interfaces and Types

- `InkNotebook` schema 从 `1` 迁移到 `2`，新增页面顺序和页面删除墓碑字段。
- `normalizeNotebook()` 必须兼容旧 schema 1 并补齐新字段。
- `mergeNotebooks()` 的页面顺序、删除和新增合并规则成为持久化兼容约束。
- `NotebookStore.save()` 解析失败时改为失败返回，不再静默恢复并覆盖文件。
- `NotebookStore.observe()` 保持按 `.ink` 文件回调的兼容形态，但内部增加事件去重和自身写入抑制。
- `TileRenderer` 增加当前页局部 stroke 查询接口，供橡皮擦使用。
- 新增 `ink` Markdown code block processor，语法固定为“第一行路径、可选第二行 page ID”。

## Test Plan and Acceptance

### Unit and integration regression

新增确定性测试覆盖：

- 损坏 JSON 保存时：
  - `vault.process()` 不返回新内容；
  - 原始文本保持不变；
  - 调用方收到可识别错误。
- 保存失败后：
  - dirty revision 保留；
  - 后续显式 flush 可以再次尝试；
  - 不产生未处理 rejection；
  - 关闭和切换文件 Promise 能正常结束。
- 关闭或切换文件时活动笔迹完整保留并进入保存快照。
- `pointercancel` 不采集 cancel 坐标。
- pointerdown 后切换工具或页面时，结束结果仍归属于原 interaction 的工具和页面。
- 延迟 capture-loss 不会结束新一代 pointer interaction。
- 橡皮擦单击删除后立即触发 render，旧 tile 不再显示。
- 橡皮擦局部查询只访问空间索引候选，不扫描整页全部笔迹。
- 删除早期 stroke 不会导致无关 stroke 所在 tile revision 变化。
- 同一 PointerEvent 的多采样只读取一次布局 rect。
- 套索拖动使用缓存的选区数据，结束时正确生成 undo/redo。
- 页面删除、复制、移动、最后一页保护和 undo/redo。
- schema 1 到 schema 2 迁移。
- 并发新增、页面删除、页面排序和墓碑合并不会复活已删除页面。
- Vault modify 事件只刷新对应文件，并能处理 debounce、并发刷新、自身保存事件和读取错误。
- Markdown `ink` block 的有效路径、指定页面、省略页面、错误路径、损坏文件和文件更新刷新。

### Browser and visual regression

使用现有 preview 基础设施增加 Playwright 回归，覆盖：

- `360px` 手机；
- `480px` split pane；
- `720px` 平板；
- `1280x720` 桌面。

每个尺寸验证：

- 一级工具可见且可操作；
- 无横向滚动导致的隐藏功能；
- 工具栏高度和画布占比达到门槛；
- 页面 rail 展开/折叠不覆盖画布；
- 弹层、焦点和 Escape 行为；
- 浅色主题、深色主题和高对比变量下文字/边框/选中状态可读；
- 画布非空，纸张、笔迹和 Markdown 预览按预期渲染；
- 截图 diff 不出现控件重叠、文字截断或布局跳动。

真实 Obsidian、Apple Pencil、移动端内存压力和跨设备同步仍需在发布前进行人工验证；这些不由 jsdom 或 preview 测试替代。

## Assumptions and Delivery Gates

- 本次完整范围包含技术 P1/P2/P3 与产品/UX P1/P2，不再继续扩展 OCR、搜索文本、反向链接、图片/PDF 导出等其他原生能力。
- Markdown 嵌入只读；编辑仍通过 `.ink` 视图完成。
- 页面排序采用带时间戳的 notebook 级最后写入优先策略，并确定性补入并发新增页面；不实现复杂的 CRDT 排序。
- 不引入新的运行时依赖，继续复用 Obsidian API、现有 rendering 和 tile 基础设施。
- 实现分为两个可回滚提交阶段：
  - 阶段 1：数据安全、pointer 生命周期、保存队列、空间索引和 Vault 事件；
  - 阶段 2：schema 2 页面生命周期、Markdown 嵌入和 UI/响应式重构。
- 每阶段完成后执行 `npm run typecheck`、`npm test`、`npm run build`，并追加 `plan/status/COMPLETED-UPDATE-LOG-x.md`。
- 全部阶段通过后建议发布为 `0.2.0-beta.1`；若只交付阶段 1，则建议为 `0.1.0-beta.6`。
- 实现过程应保持在当前 Local 仓库目录，不创建仅存在于临时 Worktree 的最终修改；完成后创建英文原子 commit，并准备包含风险、验证、发布和回滚方式的 PR 描述。
